## 2. 通用约定

- 编号：`P4-01`…；spec 文件名 `tests/e2e/04-permission-matrix.spec.ts`（P1 起用 `05-`、`06-`…）。

- 数据：临时实体统一 `E2E_` 前缀，`afterAll` 先用户后角色逆序删除；
  角色被引用时后端返回 `code=1003`，清理必须先删用户。

## 3. P4 权限矩阵（本轮实现）

权限来源：`fams-frontend/src/config/permissions.js` 的 39 个叶子权限码；
后端 `PermissionPolicy` 按「集合 key × 方法」映射权限码，`JwtAuthFilter` 每次请求重算权限
（停用角色/改权限立即生效）；前端 `userStore.can()` 基于 `org-roles` 的启用角色计算，刷新后生效。

### 3.1 菜单与路由（P4-01 ~ P4-05）

| 编号 | 场景 | 角色权限 | 关键断言 |
| --- | --- | --- | --- |
| P4-01 | 最小权限只能看到工作台 | `wm:view` | 菜单含「工作台」，不含「固定资产 / 低值资产 / 组织架构 / 系统管理」；登录后停在 `/workbench` |
| P4-02 | 无 `wm:view` 时按可访问页落地 | `fa:view` | 登录后被守卫送到 `/fixed-assets`；菜单出现「固定资产 → 资产管理」，无「工作台」 |
| P4-03 | 直链越权兜底 | `wm:view` | 直接访问 `/system/role` 后 URL 回到 `/workbench`，页面不白屏、不落 403 |
| P4-04 | 无任何可访问页落 403 | 空权限 | 登录后 URL 为 `/403`，页面含「无访问权限」 |
| P4-05 | 按钮级不渲染 | `fa:view` | 资产台账无「新增资产」「删除」；对照组（admin）同页有「新增资产」 |

> P4-02/P4-03/P4-04 会触发 `/api/org-users` 的 403（普通角色读不到用户表），
> 用例需 `allowStatus: [403]` 并放行「无权限访问该数据」的控制台/未捕获异常（与 SMK-07 同款）。

## 5. P2 低值资产主流程（已实现，P2-01 ~ P2-22）

spec：`tests/e2e/07-low-value-flow.spec.ts`。库存规则来自契约 `stock` 声明：

```text
入库  low-value-inbound     : DONE 时 stock += quantity
领用  low-value-requisition : PROCESSING 预占 reserved，DONE 扣 stock + 释放预占，REJECTED/REVOKED 释放
退库  low-value-return      : DONE 时 stock += quantity；可退额度 = DONE 领用 − DONE 退库 − PROCESSING 退库
```

| 编号 | 场景 | 断言要点 |
| --- | --- | --- |
| P2-01 | 新建物品在台账可见 | 页面搜索命中、显示物品名；接口 `stock` 一致 |
| P2-02 | 物品编码重复 | 409 + 提示重复 |
| P2-03 | 物品必填缺失 | 422 |
| P2-04 | 入库单直接 DONE | `stock += quantity` |
| P2-05 | 入库草稿 → DONE | 草稿不动库存；改 DONE 后回补 |
| P2-06 | 入库缺数量 | 422 |
| P2-07 | 领用草稿 | 库存与预占都不变 |
| P2-08 | 领用提交 | `reserved += quantity`，`stock` 不变 |
| P2-09 | 领用通过 | `stock -= quantity`，`reserved` 归零，状态 `DONE` |
| P2-10 | 领用驳回 | 预占释放，库存不变 |
| P2-11 | 可用库存不足 | 提交返回 1001，单据仍为 `DRAFT`，库存与预占不变 |
| P2-12 | 已完结改状态又改数量 | 409「单据已生效，不能修改数量」 |
| P2-13 | 删除已完结领用单 | 库存回补 |

| P2-15 | 退库通过 | 库存回补，状态 `DONE` |

## 8. P10 盘点专项（已实现，P10-01 ~ P10-12）

盘点是「计划 → 盘点单 → 正式审批 → 结论落地」的长链路，历史上只做过界面点测，
链路上的问题（假明细、空单送审、审批对象可改、审批被跳过、盘亏落不了地、盘盈不建账）一个都没被用例覆盖。
本轮按接口级断言把盘点闭环补齐，文件为 `tests/e2e/18-inventory-flow.spec.ts`。

| 编号 | 场景 | 断言要点 |
| --- | --- | --- |
| P10-01 | 盘点明细引用真实资产 | 明细 `assetId/assetNo/assetName` 与台账逐项一致，不再出现 `A01` 这类假编号 |
| P10-02 | 未盘完不允许送审 | 明细仍有 `UNCHECKED` 时送审返回 400，文案含「未登记盘点结果」，单据停在 `DRAFT` |
| P10-03 | 盘完送审 → 审批到底 → 盘亏落地 | 结果确认、差异复核（资产管理员 R2）→ 审计抽查（审计员 R6）三环走完为 `DONE`；盘亏明细生成 `DRAFT` 处置单且带真实 `assetId` |
| P10-04 | 伪造 `hasDiff` 不能跳过审批环 | 明细有盘亏却传 `hasDiff=false` 时，服务端仍按明细事实判定有差异，审批一次后仍是 `PROCESSING` |

### 8.1 前置条件与注意

- 盘点明细取台账真实资产（`fixed-assets`），按公司分组取资产最多的一家。
- 64KB 场景由用例自己造（长备注撑大明细），不再依赖台账里恰好有多少资产：
  导入批次一变，「资产量不足」的旧前提就会误报失败。
- 审批人临时创建：资产管理员 `ROLE_ASSET`、审计员 `ROLE_AUDITOR`、仓管员 `ROLE_WAREHOUSE`，
  用完随单据一起清理。
- 清理顺序必须是「先删单据（审批中的先撤销）→ 再删临时账号」：单据删除会级联清审批轨迹，
  轨迹还在时账号会被「该用户已有审批记录，不能删除」拦下。
- 盘盈建账会产生新台账行（新资产被入库单引用时不能先删资产），盘亏会把被盘资产置成
  「待核销」；`afterAll` 按「先删入库单 → 再删新建资产 → 最后把资产状态还原成用例执行前」收尾，
  不在生产库留残余状态。
- 用例跑在生产形态地址上（`http://localhost`），只留 `E2E_` 前缀数据，不自动清库。
