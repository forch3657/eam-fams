# 纵向审批（按部门解析审批人）

## 背景

改造前，审批环节只配置「系统角色」，后端按角色成员判定：

```java
ids.addAll(service.userIdsOfRole(text(step.get("approverRoleId"))));
```

后果是：

- 任何持有 `ROLE_LEADER` 的账号都能审批**任意部门**的单据（`mode=ANY` 还是「或签」，一人通过即过）；
- 「分管副总审批」环节同理，任意一个 `ROLE_VP` 都能批；
- 数据范围（`dataScope=DEPT`）只作用于**列表查询**，不作用于审批动作，绕开列表直接调接口也能越权审批。

这与「行政的职员由行政的经理审批、再由行政的分管领导审批」的实际管理口径不符。

## 现在的规则

审批人从「角色成员」改为「按单据归属部门解析到具体的人」：

| 环节类型 `approverType` | 审批人 | 是否唯一 |
|---|---|---|
| `ROLE`（缺省，兼容历史流程） | 持有 `approverRoleId` 的启用账号 | 否（仍按 `mode` 或签/会签） |
| `DEPT_LEADER` | 单据归属部门的**部门负责人** | 是 |
| `PARENT_DEPT_LEADER` | 上级部门负责人 | 是 |
| `DEPT_VP` | 单据归属部门的**分管领导**（本部门没配则向上找父部门） | 是 |
| `USER` | 环节上指定的固定账号 | 是 |
| `ASSET_CURRENT_USER` | 调拨单提交时生成的**调出前使用人快照** `beforeUserId` | 是 |
| `DOC_TARGET_USER` | 调拨单的**新使用人** `toUserId` | 是 |

> 后两类为 WF5 调拨交接确认新增（2026-11-11）。`ASSET_CURRENT_USER` 必须配 `HAS_ASSET_USER`
> 触发条件：空闲资产没有使用人时该环节不生效，否则提交时的 fail-closed 预解析会把它拦成 400。
> 快照由服务端 `ApprovalService.snapshotTransferSource` 按台账生成，不采信客户端，审批期间资产被改也不换审批人。

「唯一」意味着：`mode` 不再影响判定，只允许负责人本人通过；人员不在岗时走**转办/加签**，而不是放开整个角色。

### 单据归属部门怎么定

优先级固定，前后端一致：

1. 单据自身的 `deptId`（低值领用/退库/入库）；
2. 资产的 `deptId`（固资 8 类单据表里没有 `dept_id`，必须先看资产）；
3. 单据创建人所属部门。

后端实现 `ApproverResolver#deptIdOf`，前端实现 `services/approval.js#docDeptId`，两处口径一致。

### 缺配置时的行为

- 提交时**预解析全部生效环节**，任一环节解析不到审批人 → 直接 400，并点名环节与角色：

  ```
  以下环节没有可用的审批人，请先在「组织架构」中指定：部门主管确认（部门负责人）
  ```

  该校验对**所有**生效环节生效：部门负责人 / 分管领导缺失会被拦下，归口角色（财务、仓管、审计）无人时同样会被拦下，避免单据提交后无人能批、长期挂起。

- 审批时无权 → 403，并点名**该由谁批**（部门维度会点名到具体的人，不再只报角色名）：

  ```
  当前环节「使用部门确认」需要由「王强」审批
  ```

## 配置位置

### 1. 指定部门负责人 / 分管领导

`系统管理 → 组织架构 → 部门` → 编辑部门：

- **部门负责人**：从本公司在职用户中选择（存 `leader_id`，同时回写 `leader` 文本列供列表/导出兼容）；
- **分管领导**：同上（存 `vp_id`）。

存量数据可用迁移脚本回填（见 `fams-backend/sql/04-maintenance/`）：

| 脚本 | 作用 |
|---|---|
| `01-dept-approver.sql` | 加 `leader_id` / `vp_id` 两列，并按姓名回填 |
| `02-dept-approver-backfill.sql` | 按「部门主管 / 分管副总」角色回填初值，并输出仍缺配置的部门清单 |
| `03-flow-approver-type.sql` | 把流程环节从 `ROLE` 改为 `DEPT_LEADER` / `DEPT_VP` |

`02` 脚本的兜底顺序（均为「只补空值」，可重复执行）：

- `leader_id`：部门内 `ROLE_LEADER` → 部门内首个启用账号 → 同公司首个启用账号；
- `vp_id`：部门内 `ROLE_VP` → 同公司首个 `ROLE_VP` → 集团内首个 `ROLE_VP`。

> 修脚本时踩过的坑：加列时 `leader_id` / `vp_id` 的默认值是**空串**而不是 `NULL`，
> 只判断 `IS NULL` 会导致兜底不生效、该部门永远补不上。脚本已改为同时覆盖 `NULL` 与 `''`。

### 2. 配置流程环节

`系统管理 → 流程配置` → 编辑环节：

- **审批人类型**：角色成员 / 本部门负责人 / 上级部门负责人 / 本部门分管领导 / 指定审批人；
- 选「部门负责人」「分管领导」时不再需要选角色，审批方式对该环节无效（唯一审批人）。

## 存量数据现状（2026-11-03 生产库）

- 生产库 29 个启用部门，`leader_id` / `vp_id` **全部补齐**（无悬空引用：指向的账号都存在且启用）；
- 其中 7 个是「空壳部门」（只挂架构节点、部门下没有启用账号，例如「至臻公司领导」「销售部」），负责人由同公司首个启用账号兼任，等真实人员到位后在组织架构里改指向即可；
- 流程环节已全部切换：`R5 部门主管 → DEPT_LEADER`、`R7 分管副总 → DEPT_VP`；2026-11-09 固定资产目标口径落地后，WF8 的「财务管理员复核 / 审计员备案」改按处置方式强制（变卖 / 捐赠 / 转让一律参与），报废仍沿用 >5 万 / >20 万金额门槛；分管副总环节仍按 >20 万触发。

## 种子流程

| 流程 | 环节 1 | 归口环节 | 金额触发环节 |
|---|---|---|---|
| 资产派发 | 使用部门确认（部门负责人） | 资产管理员登记 | — |
| 资产退库 | 部门主管确认（部门负责人） | 仓管员验收入库 | — |
| 资产借出 | 部门主管审批（部门负责人） | 资产管理员审核 | — |
| 资产变更 | 调出部门主管审批（部门负责人） | 资产管理员确认 | — |
| 资产维修 | 部门主管审批（部门负责人） | 资产管理员审核 → **修毕验收 R2**（新增末环节） | >5 万：本部门分管领导 |
| 资产调拨 | 现任使用人交出确认（快照，`HAS_ASSET_USER`）→ 调出部门主管审批（部门负责人）→ 新使用人接收确认 | 资产管理员办理调拨（末环节，DONE 回写台账） | >20 万：本部门分管领导（**前移到办理之前做事前批准**） |
| 资产处置 | 部门主管审批（部门负责人） | 财务管理员复核（变卖/捐赠/转让强制；报废 >5 万） | >20 万：本部门分管领导 + 审计备案（变卖/捐赠/转让强制） |
| 低值领用/退库 | 部门主管审批（部门负责人） | 仓管员出库/验收 | — |
| 资产入库 | 仓管验收（角色） | 资产管理员复核（角色） | — |
| 盘点 | 盘点结果确认（角色） | 差异复核 / 审计抽查 | — |

「分管副总审批」的审批人从角色成员换成该部门分管领导；金额门槛本身沿用，
但 WF8 的 `DISPOSE_FINANCE` / `DISPOSE_AUDIT` 按单据 `disposeType` 强制触发，
服务端 `effectiveCtx` 覆盖客户端 `ctx`，伪造「报废 / 低金额」无法跳过财务与审计。
WF6 新增无条件末环节「修毕验收」（R2），维修单提交即 `REPAIRING`，验收完结回 `IN_USE`。

> **例外（2026-11-04 产品口径）**：「资产入库」（WF1）与「盘点」（WF9）仍按角色池
> （`approverRoleId` = R2 / R8 / R6）判定，**不套用纵向审批**。
> - WF1 的「仓管验收 / 资产管理员复核」是**归口职能**，与使用部门无关，按部门解析反而会让归口人员批不了；
> - WF9 的盘点单覆盖整家公司、明细横跨多个部门，「单据归属部门」这个维度在盘点上不成立，
>   按某一个部门解析负责人/分管领导没有业务含义，还容易让跨部门盘点单卡在找不到审批人。
>
> 这两条流程在流程配置里保持 `approverType` 缺省（ROLE），是有意保留的例外，不是漏改。
> 若将来把盘点单改成「按部门拆单生成」，再评估是否切换到 `DEPT_LEADER` / `DEPT_VP`。

## 已知边界

- **审批人待办可见性（2026-11-11）**：`DEPT_ONLY`（R3 资产使用人）按 `creatorId` 只看本人创建的单据，会漏掉「别人提交、当前环节点名到本人」的待审单据——WF5「新使用人接收确认」曾因此让陈学知在工作台看不到待办、业务页签 0 条。`GenericService.approverNeedsUnscopedDocs` 对 `DEPT_ONLY + wm:todo` 的固资单据列表放行数据范围过滤；审批动作仍由 `requireApprover` 按流程点名到人复核，写 / 删仍由 `PermissionPolicy` / `AssetOwnerPolicy` 控制，列表可见不等于可审批。
- **WF1（资产入库）与 WF9（盘点）是纵向审批的明确例外**：前者是仓管/资产管理员的归口职能，后者因盘点单跨部门而不适用部门维度；两者继续按角色池判定，详见「种子流程」后的例外说明。
- 负责人在单据审批期间被调整，历史在途单据按「实时解析」执行，可能出现需要转办的情况；如需更强的一致性，可在提交时把审批人快照进单据（后续增强项）。
- 部门负责人/分管领导为空的部门，涉及该部门单据的提交会被拦下，需要先在组织架构中指定；空壳部门当前由同公司账号兼任。
- 一人兼任多个部门负责人时，按单据归属部门分别解析，互不影响。
- 403 文案从「需要由「部门主管」审批」改成点名具体的人，依赖旧文案的用例/断言需要同步调整。
