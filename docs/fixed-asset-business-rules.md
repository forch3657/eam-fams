> 状态：**业务规范（2026-11-09 用户已裁决全部核心口径：第 1~6 项 + 归还载体 + 期初切换日取法）**。本文定义「业务应该怎样」，不是当前系统已实现的行为。

## 1. 总则：符合常理的六条底线

1. **单据驱动、账实一致**：资产**业务状态的流转**（派发 / 借出 / 归还 / 维修 / 处置 / 核销）只允许由已完结（`DONE`）的业务单据或审批动作改变，不允许在台账上手工直改状态来"造闭环"。两类主数据动作不在此限：① **新增资产登记**＝建档录入，直接落初始状态 `IDLE`，不生成入库单；② **期初导入**＝上线切换日前的历史数据整体例外，标注来源留痕、不倒补单据（见 §7.2）。WF1 入库验收是**实际资产入库**这一独立业务动作，只负责 `PENDING_INBOUND → IDLE`，不是新增登记的必经环节。
2. **变更 ≠ 处置**：资产变更是「在册继续使用」，改变的是使用部门/使用人/地点/状态，不改变资产的存在与权属；资产处置是「退出台账」，改变的是资产是否在册。两者不能共用同一分类字典。
3. **串行与互斥**：一次业务动作必须有明确的前置资产状态；资产处于借出/维修/待核销/已核销时，不得再发起与之冲突的动作。审批中的单据锁住该资产，不允许并发改单。
4. **发起、审批、验收分离**：发起人不自批；涉及实物进出的动作必须有第二人验收（仓管/资产管理员）；涉及金额或资产退出的动作必须有财务/审计/分管领导按额度参与。
5. **全程留痕**：每次动作落单据、落审批轨迹、落操作人/时间；归还、验收、核销这类"闭环动作"也必须留痕，不能只改一个布尔字段。
6. **分类口径唯一**：一个业务概念只在一处定义（枚举 + 字典 + 单据字段），前后端由契约导出，不允许多套同义词并存。

## 2. 业务分类（用户 2026-11-09 确认）

### 2.1 资产变更（在册、继续使用）

| 子类型 | 定义 | 影响字段 | 状态变化 | 不改变 |
|---|---|---|---|---|
| 调拨 `TRANSFER` | 公司内部跨部门/跨公司/跨地点/换使用人的资产转移 | `deptId`、`userId`、`companyId`、`location` | 可短暂置「调拨中」，完结后回到 `IDLE` 或 `IN_USE` | 资产在册、原值、折旧、权属 |
| 维修 `REPAIR` | 送修、维修中、修毕验收回用；可带维修费用与供应商 | `repairStatus`、维修记录、费用 | `IN_USE/BORROWED → REPAIRING → IN_USE` | 资产在册、使用人、部门 |
| 信息更正 `CORRECTION` | 更正名称、分类、原值、购置信息、存放地点等台账字段 | 对应台账字段 + 更正前后值 | 不变 | 资产在册、状态、使用人 |

- **三类都属于「资产变更」大类**（用户 2026-11-09 确认），共用一张变更单与一条变更流程，靠 `changeType` 区分子类型，而不是多张互不相干的单据。
- 信息更正必须走审批并留「更正前 → 更正后」快照，不允许直接编辑台账字段绕过留痕；是否重算折旧基数见 §7.3。

### 2.2 资产处置（退出台账）

| 子类型 | 定义 | 完结结果 | 关键要素 |
|---|---|---|---|
| 报废 `SCRAP` | 达到使用年限或毁损，无残值/有残值回收 | 台账 `DISPOSED`，保留行留痕 | 报废原因、技术鉴定、残值 |
| 变卖 `SALE` | 有偿出售给外部单位 | 台账 `DISPOSED` | 评估价、成交价、受让方、收款凭证 |
| 捐赠 `DONATE` | 无偿转出给外部单位 | 台账 `DISPOSED` | 受赠方、捐赠协议、审批依据 |
| 转让 `TRANSFER_OUT` | **集团内独立核算主体之间**的权属转移；一旦出公司即出账 | 台账 `DISPOSED` | 受让主体、转让价/无偿、权属凭证、出账依据 |

- 四种方式共用一张处置单与一条处置流程（WF8），靠 `disposeType` 区分；都要经过「待核销 → 已核销」，台账**保留行**用于审计，不物理删除。
- **变卖 / 捐赠 / 转让一律强制财务 R4 + 审计 R6 参与，不设金额门槛**（用户 2026-11-09 确认）；报废沿用现有按金额加环节的规则。
- **转让 vs 调拨的边界**：调拨是公司**内部**使用部门变化，资产仍在账；转让**只含集团内独立核算主体之间**的权属转移，且在「出公司」这一刻出账，以资产 `companyId` 是否变化判定。这是最容易被混淆的一对概念。

### 2.3 现状分类错配（必须改）

| 字典 | 生产库当前取值 | 目标取值 | 差距 |
|---|---|---|---|
| `change_type`（资产变更类型） | `TRANSFER` 调拨、`REPAIR` 维修、`OTHER` 其他 | `TRANSFER` 调拨、`REPAIR` 维修、`CORRECTION` 信息更正 | 需停用 `OTHER`、新增 `CORRECTION` |
| `dispose_type`（处置方式） | `SCRAP` 报废、`SALE` 变卖、`TRANSFER` **调拨**、`OTHER` 其他 | `SCRAP` 报废、`SALE` 变卖、`DONATE` 捐赠、`TRANSFER_OUT` 转让 | **把调拨错放处置；缺捐赠、转让；`TRANSFER_OUT` 仅限集团内独立核算主体** |

枚举源：`fams-frontend/src/constants/enums.js:90-102`（`DISPOSE_TYPE` / `CHANGE_TYPE`），导出契约 `fams-backend/src/main/resources/contract/enums.json:53-63`，生产库字典 `system_dict_items`（`dict_code = dispose_type / change_type`）。按项目约定，**契约由前端 schema 导出，只改后端字典会被下次导出抹掉**，改造时必须同时改 `enums.js` → `export:contract` → 字典迁移脚本。

## 3. 全生命周期（目标顺序）

统一约定：所有业务单据 `DRAFT → PROCESSING → DONE`；**只有 `DONE` 才允许回写台账**；审批中该资产被锁定。新增资产登记与期初导入属主数据动作，不生成业务单据。

### 阶段 0 · 建账（主数据）

| 入口 | 性质 | 单据 | 台账结果 |
|---|---|---|---|
| 新增资产登记 | **登记建档**（主数据录入） | 无（不生成入库单） | 直接 `IDLE`，资产即可用 |
| 期初导入 | 上线切换日前的历史数据例外 | 无（历史例外） | 允许直接写状态，标 `sourceTag=期初导入` + 批次号并告警 |
| 盘点盘盈 / 账外资产 | **实际资产入库** | 自动生成 `DRAFT` 入库单 | `PENDING_INBOUND` → WF1 验收后 `IDLE` |

**概念边界（用户 2026-11-09 确认）**：新增资产是**登记**，入库是**实际资产入库**，两者是不同性质的动作，不是同一流程的两个阶段，因此不要求「新增 → WF1 → 可用」强制串行；保持现状没有问题。WF1 只处理待入库的账外 / 盘盈资产。

期初过渡口径（已裁决，见 §7.2）：以**管理员指定的上线切换日**为界，切换日前导入的资产整体视作期初数据，直接承认其状态合法、**不倒补入库单**，仅以 `sourceTag=期初导入` + 导入批次号留痕并在报表/审计中单列；切换日后关闭该口子，此后新增一律走「新增资产登记」。期初资产后续可正常派发 / 借出 / 变更 / 处置，不需要补建历史验收单；已核销的期初资产直接留在 `DISPOSED`，不进入盘点可用数。

### 阶段 1 · 入库验收（WF1，实际资产入库）

- 定位：针对**待入库的账外 / 盘盈资产**办理实物入库，不是新增登记的后续环节。
- 发起：资产管理员 R2；前置：资产为 `PENDING_INBOUND`。
- 审批：仓管验收 R8 → 资产管理员复核 R2。
- 完结：`IDLE`（空闲）+ 写入库日期；验收不通过退回 `DRAFT`。
- 关键：入库单必须关联到具体资产（`assetId` 必填），否则无法形成实物闭环；资产下拉应只列 `PENDING_INBOUND`，避免对已 `IDLE` 资产发起无效入库单。

### 阶段 2 · 领用与借出

| 动作 | 发起 | 前置状态 | 审批链 | 完结后台账 | 后续 |
|---|---|---|---|---|---|
| 派发 WF2 | R2 | `IDLE` | 使用部门主管 → 资产管理员登记 | `IN_USE` + `userId`=**实际领用人**、`deptId`=领用部门 | 可借出/变更/退库 |
| 借出 WF4 | R3 | `IN_USE` | 部门主管 → 资产管理员审核 | `BORROWED`（保留 `userId/deptId`） | 归还退库 / 逾期预警 |
| 退库 WF3（普通退库 / **借出归还**） | R3 / 借用人 | `IN_USE` 或 `BORROWED` | 部门主管确认 → **仓管验收 R8** | `IDLE` + `userId=null`；归还型同时回写借出单 `returned` 等字段 | 可重新派发 WF2 |

- **借出归还不再独立成单**：归还就是**关联原借出单的退库单**（WF3），不新建归还单、不新建流程。复用 WF3 已有「部门主管确认 → 仓管验收入库」审批链，天然满足「归还升级为仓管验收的审批型动作」。
- 退库单新增可空字段 `borrowDocId`：**非空即归还型**，须指向 `DONE` 且未归还的借出单；用于前置校验、防重复归还、以及资产详情里「借出 → 归还退库」的闭环轨迹。普通退库该字段为空。暂不新增 `sourceType` 枚举，按 `borrowDocId` 是否为空即可区分与筛选。
- **口径后果**：归还后资产**回仓库**（`IDLE`、清空 `userId`），不再回原使用人 `IN_USE`；如需继续使用须重新派发 WF2。这与当前 `registerBorrowReturn`（`BORROWED → IN_USE`）不同，是本次裁决带来的实质变化。
- 借出应有预计归还日与逾期状态；当前没有到期日字段（见第 5 节）。

### 阶段 3 · 在用期间

| 动作 | 发起 | 前置 | 审批链 | 完结后台账 |
|---|---|---|---|---|
| 变更-调拨 WF5 | R2 | `IDLE` / `IN_USE` | 调出部门主管 → 资产管理员 →〔大额〕分管副总 | 更新 `deptId/userId/location`，状态回到可用 |
| 变更-维修 WF6 | R3 | `IN_USE` / `BORROWED` | 部门主管 → 资产管理员 →〔大额〕分管副总 | `REPAIRING` → 修毕验收 → `IN_USE` |
| 盘点 WF9 | R2 | 计划 + 盘点单明细全登记 | 盘点结果确认 R2 →〔有差异〕差异复核 R2 → 审计抽查 R6 | 盘盈建账/入库、盘亏待核销+处置、异常转维修/变更 |

盘点闭环细则沿用 `README.md:195-215`：差异由服务端判定，派生单据独立事务，计划与盘点单靠 remark 关联。

### 阶段 4 · 退出（处置 WF8）

- 发起：资产管理员 R2；前置：资产 `PENDING_WRITE_OFF`（待核销）或经审批允许直接申请。
- 审批：部门主管 →〔>5万〕财务 R4 →〔>20万〕分管副总 `ALL` + 审计 R6 备案；**变卖 / 捐赠 / 转让三类一律强制财务 R4 + 审计 R6 参与，不按金额豁免**（已确认）；报废沿用金额门槛。
- 判定「出公司」：以资产 `companyId` 是否变化为准；集团内独立核算主体之间的转移走转让（出账），公司内部门之间走调拨（在册）。
- 完结：`DISPOSED`（已核销），台账保留留痕；同时停折旧、写处置方式与凭证号。
- 禁止：已核销资产再被派发/借出/变更/盘点计入可用数量。

### 阶段 5 · 横切

折旧（按月计提、处置当月停提）、报表（分类/位置/部门/使用人统计 + 下钻明细）、资产详情「操作记录」只展示真实单据、审计日志。

## 4. 状态机（目标）

### 4.1 资产状态

| 状态 | 含义 | 可由谁写入 |
|---|---|---|
| `PENDING_INBOUND` 待入库 | 已建账、待实物验收入库 | 盘盈建账 / 账外资产登记 |
| `IDLE` 空闲 | 在库可用 | 新增资产登记 / WF1 入库 / WF3 退库（含借出归还） |
| `IN_USE` 使用中 | 已派发到使用人 | WF2 派发 / 维修完成 |
| `BORROWED` 借出中 | 临时借出 | WF4 借出 |
| `REPAIRING` 维修中 | 送修未回 | 变更-维修 |
| `PENDING_WRITE_OFF` 待核销 | 已批准待处置 | 盘点盘亏 / 处置申请 |
| `DISPOSED` 已核销 | 退出台账，留痕 | WF8 处置 |

「调拨中」建议作为单据级状态而非资产状态，避免与 `REPAIRING` 等并列膨胀。

### 4.2 状态转换（只允许下列路径）

```
新增资产登记(建档) --------------------> IDLE
盘盈/账外 → PENDING_INBOUND --WF1(实物入库)--> IDLE
IDLE --WF2--> IN_USE --WF3(普通退库)--> IDLE
IN_USE --WF4--> BORROWED --WF3(归还退库,仓管验收)--> IDLE
IN_USE / BORROWED --维修--> REPAIRING --验收--> IN_USE
任意可用态 --调拨--> 更新归属字段，状态不变
任意可用态 --盘点盘亏--> PENDING_WRITE_OFF --WF8--> DISPOSED
```

### 4.3 互斥规则（目标）

1. `BORROWED` 不得再借出、派发；其退库只能走关联该借出单的归还型退库单；`REPAIRING` 不得派发/借出。
2. `PENDING_WRITE_OFF` / `DISPOSED` 不得发起任何在册业务。
3. 同一资产同一时刻只允许一张 `PROCESSING` 单据（借出/维修/调拨/处置互斥）。
4. 审批中（`PROCESSING`）资产锁定，改单/删单被 409 拒绝。
5. 归还型退库单必须关联 `DONE` 且未归还的借出单，一张借出单只允许一张有效归还退库单；`returned` 由退库单 `DONE` 时回写，不允许手工改。

### 4.4 单据状态

`DRAFT → PROCESSING → DONE`；`REJECTED` 可修改后重提交；`REVOKED` 为终态禁止改删。注意 `APPROVE_RESULT`（SUBMIT/AGREE/REJECT/WITHDRAW/VOID/TERMINATE/REVOKE/ADD_SIGN/TRANSFER/CC）是**轨迹结果码**，不是单据状态，不可混用。

### 7.2 已裁决：登记 / 入库语义边界、期初过渡与归还载体（2026-11-09）

**6a 概念澄清（用户口径）**：「新增资产是登记，入库是实际资产入库」。二者是**不同性质的动作**，不是同一流程的两个阶段：

| 动作 | 性质 | 是否产生单据 | 台账结果 |
|---|---|---|---|
| 新增资产登记 | 主数据建档录入 | 否 | 直接 `IDLE`，资产即可用 |
| WF1 入库验收 | 实际资产入库（实物验收） | 是，`DRAFT → … → DONE` | `PENDING_INBOUND → IDLE` |

因此保持现状（新增不强制走 WF1）不构成 §1 第 1 条的例外或破功：该条约束的是**业务状态流转必须由已完结单据驱动**，而登记是建账时的初始状态录入，本身不产生状态流转。WF1 的适用对象收窄为待入库的账外 / 盘盈资产，仍须 `assetId` 必填并经仓管验收。落地时只需在界面文案与「入库单资产下拉」上把两者区分清楚。

**6b 期初导入过渡（保留历史例外）**：

| 项 | 口径 |
|---|---|
| 适用范围 | 仅上线切换日前导入的历史资产；低值资产期初库存同理（直写 `stock`、不生成入库单） |
| 状态 | 直接承认导入的状态合法，含 `BORROWED` / `REPAIRING` / `DISPATCHING` / `DISPOSING`，告警但放行 |
| 留痕 | `sourceTag=期初导入` + 导入批次号；报表/审计单列，**不批量补录 `DONE` 入库单、不造假单据** |
| 硬边界 | 切换日由**管理员在系统设置中手工指定**，一经生效不得随意回改（指定/变更写操作日志）；此后关闭期初口子，新增一律走「新增资产登记」；`sourceTag=期初导入` 不得被日常新增复用 |
| 后续业务 | 期初资产正常派发 / 借出 / 变更 / 处置，无需补建历史验收单；已核销的留在 `DISPOSED`，不进入盘点可用数 |

**7 归还载体（用户追加裁决）**：归还单即退库单，退库单关联借出单。代码核对结论：二者合并可复用 WF3 已有审批链，但会带来一处实质变化——**归还后资产回仓库 `IDLE`、清空 `userId`，不再回原使用人 `IN_USE`**；如需继续使用须重新派发 WF2。`back` 目前走 8 类单据共用的动态契约模板，须拆为独立静态契约后再加 `borrowDocId`。
