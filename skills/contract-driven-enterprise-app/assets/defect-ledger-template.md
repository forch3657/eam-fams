# 逃逸缺陷台账

> 规则：当天登记；命名 `[BUG-xxx]`；写明真实角色与完整 UI 路径；每条补一条负向断言用例。只修代码不补用例不算回灌。

## 回灌规则

1. 缺陷在发现当天登记，编号连续，不复用。
2. 复现路径必须从登录开始写全（角色、账号、菜单、页签、按钮），不用「某页面」。
3. 预期结果与实际结果分开写；预期 4xx 类断言精确到「方法 + URL」。
4. 根因归类到：契约漂移 / 口径未裁决 / mock 与 api 分叉 / 状态机漏态 / 事务边界 / 权限漏校验 / 编码或部署产物陈旧 / 其它。
5. 每条登记后补一条自动化用例（优先负向断言），用例编号回填到台账。
6. 统计逃逸率 = 检查点之后发现的缺陷数 / 缺陷总数，用来判断门禁是否失效。
7. 高信号根因追加到 skill 的 `references/gotchas.md`。
