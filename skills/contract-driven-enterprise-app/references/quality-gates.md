# 质量门禁：构建、CI、E2E、部署、编码

门禁的价值在于「让错误在部署前被发现」。参考项目把门禁集中在唯一入口，禁止各人用自己习惯的快捷命令绕过。

## 1. 唯一构建入口

构建脚本串行执行，任一步失败即中止：

```
后端 clean package（含单测） → 前端单测 → 权限/契约漂移检查 → 前端构建
```

- 默认不要 `-DskipTests` / `--skip-tests`。长期跳过测试会让已变红的测试类无人发现，直到某次安全加固才集中爆出来。
- 只跑 `mvn test` 不产生新 jar；只跑 `npm run build` 不刷新后端接口。页面报 404 / 接口不存在 / 下载模板失败时，先核对产物的 LastWriteTime 与 java 进程 StartTime。
- 权限漂移检查至少覆盖：路由权限码、按钮权限码、契约权限资源映射、角色种子、枚举白名单。

## 2. CI 分层

三个 job 串行：后端 `clean verify`（覆盖率门禁）→ 前端 `test + build` → Playwright E2E（本地零依赖数据库或同源服务）。覆盖率阈值按模块区分（整体、安全模块、引擎模块各设下限），不要一刀切。

构建期注入版本标记（git hash + `dist/version.txt`），运行时提示前后端版本不一致，避免「明明改了却没生效」的扯皮。

## 3. 契约变更与生产重建顺序

```
改前端 schema → 运行 export:contract → 核对产物 git diff
→ 补迁移 SQL（DDL 由管理员账号执行）→ 跑 check:perm 与后端单测
→ stop-prod → build-prod → start-prod
```

- 停服务在前：Windows 下运行中的 jar 会锁住 `target`，直接 `mvn clean package` 会报「Failed to delete ...jar」。
- 重建顺序不能颠倒；重建后说明站点会短暂不可用。
- 迁移脚本要幂等，且同时处理 `NULL` 与空串的历史数据。

## 4. E2E 分期与运行

- 固定顺序：权限矩阵 → 固定资产主流程 → 低值资产 → 审批中心 → 报表/导入/工作台；专项（盘点、部门审批、真实组织回归）作为附加批次。
- 配置要点：单 worker、trace on、失败截图/视频、`baseURL` 由环境变量决定、产物按 runId 归档。
- 真实 UI 登录：token 存 `sessionStorage` 时 `storageState` 无法跨 context 复用，每个用例走真实登录。登录按钮文案可能含空格（如「登 录」），正则要容错。
- Element Plus 交互坑：`el-switch` 点包装元素而非隐藏 input；`el-select` 用 `innerText` 读选中值，`inputValue` 恒为空；SPA 深链可带 query 直达页签。
- 不要加 `--reporter=list`，它会覆盖 html reporter 导致报告不更新。
- 预期 4xx 断言必须精确到「方法 + URL」；不接受整页 403 就放行。

## 5. 测试数据安全（红线）

- **E2E 代码与脚本绝不自动清空任何业务数据**，也不要新增自动清库脚本。整体清空/重导是人工动作，由用户通过系统内导入功能完成。
- 临时数据统一 `E2E_` 前缀；`afterAll` 按「先用户后角色」逆序删除，被引用时按错误码处理。
- 隔离测试库若存在，仅在用户明确要求时启用；默认跑生产库时更要严守前缀与自清理。
- 只删 `E2E_` 前缀数据的维护脚本可以存在，但必须由人按需执行；删除账号要排在删除审批轨迹之后。
- 用例的前置条件不能依赖生产库的数据量（清库后条数会变），需要体量就自己造数据。
- 会改写生产数据的用例必须按执行前快照还原状态。
- 应用账号只有 DML 无 DDL：`DROP/CREATE DATABASE` 不要用应用账号尝试；管理员口令不写仓库。

## 6. 部署约定

- 入口层：`index.html` 设 no-cache + SPA 回退，否则两级路由刷新白屏；前端构建 `base` 用根路径。
- 后端只监听回环 + `forward-headers-strategy: native`，避免 HTTPS 入口被判跨域 403。
- 启动脚本先杀干净同名的入口进程再拉起干净实例，避免多个实例抢端口。
- 隔离环境配置里「数据库不存在即启动失败」，防止误连生产库。
- JWT 密钥在本地强随机生成并持久化到仓库外，不入库、不进前端；`.gitignore` 排除密钥目录。
- 健康检查与版本端点可匿名，其余默认拒绝。

## 7. 编码与运行时（Windows 重点）

这些坑表现为「第 1 行非法字符」「中文变问号」「CSV 少列」，容易被误判为语法或后端 bug：

- 新建/重写源码或文档后核对头字节，出现 `FF FE` / `FE FF` 即为 UTF-16LE，必须转 UTF-8。
- `.ps1` 脚本必须 ASCII-only：PowerShell 5.1 无 BOM 时按 ANSI 读取，中文字符串会乱码并破坏解析。
- 本地零依赖数据库的 SQL 初始化脚本显式声明 `encoding: utf-8`，否则中文 Windows 按 GBK 解码。
- 管理员 API 传中文时按 UTF-8 字节发送，否则变 `?????` 触发冲突。
- 导入 CSV 必须 UTF-8 BOM，解析端剥离 `\uFEFF`；**禁止用 Excel 另存 CSV**（会转 GBK 丢行，导致后端表头乱码报缺列）。
- 用占位符生成测试 CSV（`__COMPANY__` / `__DEPT__` / `__USER1__`），运行时替换，避免写死主键。
- Node 可能不在 PATH：构建脚本从预装运行时目录取最新版本注入 `$env:Path`，不要假设 `node`/`npm` 可直调。
- 明细/大文本列用 `LONGTEXT` 一类类型，避免 64KB 上限。

## 8. 发布前静态门禁

运行 `scripts/preflight.mjs --root <项目根>`，检查契约产物被单独修改、明文口令、免鉴权注解、硬编码密钥、UTF-16LE、`.ps1` 非 ASCII、CSV 缺 BOM、跳过测试、E2E 破坏性 SQL、reporter 覆盖等。

脚本是启发式扫描，WARN 需人工判断，ERROR 应修完再发布。它不替代编译、单测与人工点测。
