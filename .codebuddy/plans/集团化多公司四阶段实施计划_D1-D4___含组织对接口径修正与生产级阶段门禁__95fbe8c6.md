## User Requirements

本期仅实现系统自身独立完成的集团化多公司管理，不依赖、不实现任何外部组织架构接口或流程引擎接口。仍按 D1~D4 四个阶段交付，每个阶段必须完成并通过测试后方可进入下一阶段。同步修正组织架构对接的需求表述为：「对接人员的组织架构调整，接口对接工作联系陈国；人员组织架构信息予以保留，对接角色的权限需重新梳理与调整」，并清理文档中「删除现有人员组织」的旧描述。整体方案须满足企业级高可用、安全、可维护、可扩展要求，门禁 4 通过后即可投产。

## Product Overview

公司管理页已呈现「一级集团 → 二级研究院 → 三家三级子公司」的公司架构树。系统提供公司视角切换、按公司层级的数据可见范围、三级组织树、公司级业务隔离、集团汇总与跨公司转让闭环；本地人员、部门、公司信息完整保留，本地流程模板继续作为唯一运行来源。外部组织与流程引擎对接整体后置为「待接口」后续阶段，本期不实施。

## Core Features

- 数据可见范围按「本公司及下级 + 显式授权公司」统一管控，跨公司查看、改写、审批、导入、清空被服务端阻断。
- 顶栏由只读公司标识变为可切换公司视角；资产、单据、报表、工作台、待办、预警按所选公司呈现，新建记录自动归属正确公司。
- 组织树完整展示三级公司与下属部门；角色权限、数据范围、公司适用范围重新梳理并在本地落地。
- 集团汇总报表、按公司下钻、跨公司转让出账入账闭环、集团默认配置与公司级覆盖。
- 每阶段设放行门禁：自动测试、只读数据复核、文档同步、备份回滚演练、用户手动点测确认；任一失败即回滚。
- D4 为不依赖外部接口的投产放行与交接：上线检查单、灾备演练、权限矩阵复核签字、版本标记、交付仓同步、用户点测验收。
- 后续待接口阶段附录列出需向陈国、术欢、杜娟确认的接口与配置前置条件，接口到位后另立计划。

## Implementation Approach

采用「门禁式渐进改造」：先把服务端数据范围收敛为唯一断言入口，再开放界面能力，再做集团汇总、转让闭环与工程化，最后以投产放行与交接收口。范围收缩后，外部组织同步与流程引擎对接不进入本期，投产不再被未就绪接口阻塞。

关键决策与权衡：

1. 统一断言下沉到服务层而非仅 Controller：`ApprovalService`、`DataImportService`、`DataResetService`、`DepreciationService` 会直调 `create/update/patchField/writeQuietly`，只在 Controller 加校验会留旁路；新增 `RowScopeGuard` 作为所有读写路径必经断言，Controller 保留权限码与 `AssetOwnerPolicy` 兜底。
2. 公司层级用 `path` 字段 + 主体级缓存：现状 `COMPANY` 为 `company_id = 本人公司` 精确等值，`parent_id` 不参与鉴权。改为「本公司 + 全部下级 + 显式授权公司」集合，用 `IN` 条件过滤；`CompanyScopeResolver` 在主体构建时解析一次并缓存，复杂度 O(层级深度)，避免每请求递归查库。代价是公司增删改时要重算子树 path 并失效缓存。
3. 语义统一：`DATA_SCOPE` 中 `COMPANY` 标签「本公司及以下」与实现不符，`DEPT` 标签「本部门及以下」与精确 deptId 不符，`ORG_SCOPE` 存而不用；D1 一次性对齐标签、实现、orgScope 参与判定，并用迁移脚本给存量角色显式赋值，避免默认 ALL 放行。
4. 公司视角只作默认值与展示，不参与授权：前端请求头携带所选公司，服务端始终以主体授权集合为准。
5. 配置分级用「集团默认 + 公司覆盖」覆盖解析，不复制多套流程实例：`system-workflow-flows`、`system-params`、折旧方案、消息模板保持单一来源。
6. 本地组织保留：`org-companies` / `org-departments` / `org-users` 全部保留为业务外键与运行来源；本期不创建 `OrgSyncService.java`、`FlowProvider.java`，不引入外部对接抽象。
7. 避免技术债：复用契约导出、ResourceMeta 字段白名单、QuerySpec 参数化查询、审计切面与维护脚本目录；仅新增 `CompanyScopeResolver`、`RowScopeGuard` 两个组件；大类与巨型组件拆分放到 D3 渐进进行。

性能与可靠性：可见公司集合每请求一次解析并缓存；行级断言为元数据判断 + `company_id IN` 条件，配合复合索引；工作台改后端按公司分页聚合，避免一次性装载 11 类单据导致 O(N) 前端遍历；报表按公司分组用数据库聚合下钻；单号生成保持全表最大值并加索引。瓶颈在 `JwtAuthFilter` 每次请求重载主体，因此公司集合必须在主体构建时算好。

## Implementation Notes

- 契约纪律：字段、唯一性、枚举改动先改 `schema.js` 与 `constants/enums.js`，再执行 `npm run export:contract`，核对 `permission-resources.json` 并跑 `npm run check:perm`；禁止手改后端契约。新增集合须登记权限契约并配合 fail-closed 启动期校验。
- 数据库变更：生产库 `fams` 仅 DML，DDL 需 MySQL 管理员账号；脚本放 `fams-backend/sql/04-maintenance/`，命名延续 `19-` 至 `24-`，幂等、只做加法、`information_schema` 判列判索引、结尾带复核 SELECT；执行前用 `mysqldump --single-transaction` 做 `db-baseline/` 只读快照。
- 发布与部署：改动涉及已部署产物时按已授权顺序 `stop-prod.ps1 → build-prod.ps1 → start-prod.ps1` 重建重启并说明站点短暂不可用；交付到内网仓先跑 `scripts/publish/sync-repos.ps1` dry-run，确认后再 `-Apply`。
- 日志与审计：`OperationLogAspect` 扩为 append-only，补 `companyId`、traceId、IP、UA，覆盖登录、审批、导入、折旧、重置口令；失败日志沿用 200 字截断，不写口令、手机号等敏感信息，高频读请求不记日志；日志写入失败只告警不影响业务。
- 影响面控制：不改公司主键、不重导、不清库、不删除本地人员组织架构；默认 ALL 收敛前先用迁移脚本为存量角色显式赋值；`approverNeedsUnscopedDocs` 从「整体放开」改为「按当前环节点名到人」放行；公司视角与新范围语义用开关控制，可一键回退；`pickOrgUnit` 改为挑选有部门的公司，防止无部门集团公司成为列表首项。
- 测试口径：不跑自动化浏览器 E2E，点测由用户手动完成；后端全量 JUnit、前端 4 组单测、`check:perm`、`npm run build` / `mvn clean package` 为自动门禁。CSV 模板保持 UTF-8 BOM；新建源码或文档后核对头字节，避免 UTF-16LE。
- 文档同步目标文本：「2. 对接人员的组织架构调整，接口对接工作联系陈国；人员组织架构信息予以保留，对接角色的权限需重新梳理与调整。」需清理 `docs/后续升级计划20261112.txt:11`、`fams-frontend/README.md:229`、`fams-backend/README.md:88` 的旧表述；更新 `README.md` 第 7 节中「get 详情接口未做范围校验、跨公司隔离需真实多公司数据再验证」的过期结论。
